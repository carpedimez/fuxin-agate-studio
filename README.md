## 高清短开场与完整版后台准备（v0.13.0）

首页保持高细节1080p、25fps。开场从1440p源片中选择对焦清楚、无二维码的玛瑙实物镜头，按CRF20单独编码为约2.64秒的真实运动短循环，1,157,772字节；完整主循环使用原高质量1080p版本9,290,694字节，约19.48秒。开场和完整版的平均码率约3.5–3.8Mbps，比v0.12低码率版本约0.42Mbps保留更多压缩细节，不将“1080p像素尺寸”混同于真实清晰度。

首次只准备完整的高清短开场，实际帧解码后入场并持续本地循环；后台以低优先级下载完整主循环。完整版完整校验、解码且确认运动帧后，用约0.55秒透明度转场接替，旧开场层在转场结束后停止并移除。完整版仍未准备好或网络中断时，开场继续清晰播放，不改成低码率、不使用部分下载的MP4流。

两个层级都保存于CacheStorage。再次访问优先读取已缓存的完整版，不必重复等待或先下开场。暂停、离屏或原声片打开期间，不会擅自启动完整版；恢复播放后再切换。章节选择在完整版未就绪时暂存意图，开场继续播放，准备好后切到对应镜头。原有屏幕外3D停渲染、实拍背景、音乐联动和滚动吸附保留。

本地验证通过：主视频请求被挂起时开场连续循环；暂停后完成后台下载仍保持暂停；恢复后切换到完整高质量视频；断网20秒完整循环无明显等待、547帧0掉帧；再次访问仅用缓存直接播放完整版；手机和减少动态效果通过。新增开场及原完整1080p共553帧二维码检查未检出，并使用原片二维码做识别阳性对照。

这是用加载顺序和缓存换取画质与播放稳定性。第一次入场仍需取得约1.16MB开场，弱网会延后完整版出现；原片拍摄时的失焦、景深与运动模糊无法靠编码凭空恢复。来源片源、角标与原声署名保持；原声主题片使用原高质量1080p版本，点击时按需加载。以下为历史版本记录。

## 固定1080P与流畅缓存播放（v0.12.0）

首页在桌面和手机均固定1920×1080、24fps、H.264 Main，完整背景循环1,012,447字节（约1.01MB），比上一版1080p的3,742,755字节减少约73%，比旧4K的22,322,905字节减少约95%。不再读取旧4K画质记忆或自动切换720p，移除画质下拉。原声主题篇也压缩为1080p、约3.90MB；封面改为1080p版本。

原有无二维码镜头、实拍背景、音乐与原声片联动、创作、研学和整屏吸附保留。新增视频共1,298帧二维码识别未检出，保留原片阳性对照。断网整轮循环、实际帧间隔、掉帧、缓存命中、手机及3D可视范围检查归档在工作区“交付成果/1080P流畅版”。以下为历史版本记录。

## 边加载边播放与快速入场（v0.11.1）

## 运行与发布

纯静态网页，HTML、CSS、JavaScript模块与素材全部在仓库内。运行已发布网页无需安装依赖，通过任意静态HTTP服务器访问 `index.html`，或在GitHub Pages设置中选择 `main` 分支及根目录发布。

为减少首次加载请求，页面使用合并后的 `site.bundle.js` 与 `site.bundle.css`。原始模块及样式仍在仓库内，页面模板为 `index.source.html`。修改源码后执行 `npm ci`、`npm run build`，提交生成文件再推送 `main` 即可更新。

内置Three.js和样本，不依赖外部CDN。原料照片、作品收藏及研学意向仅保存在当前浏览器；更换网站地址不会自动同步旧站数据，可导出完整JSON方案后在新站导入。
